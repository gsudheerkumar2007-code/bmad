Designer: Quinn (Test Architect)

- **Total test scenarios**: 28
- **Unit tests**: 15 (53.6%)

## Test Architecture Rationale

**Navigation and layout testing strategy follows:**
- **Unit-first approach**: Pure component logic and services
- **Integration focus**: Route transitions and component interactions
- **E2E validation**: Critical user navigation journeys
- **Risk-based priorities**: Security, performance, and user experience

## Detailed Test Scenarios

### Unit Test Details

#### 1.3-UNIT-010: BreadcrumbService generates paths (P0)

**Test Case**: Core breadcrumb path generation logic
**Justification**: Critical navigation service - pure logic testable in isolation
**Mock Requirements**: Angular Router (ActivatedRoute snapshots)

**Test Scenarios**:
- Generate breadcrumbs for simple routes (/products)
- Generate breadcrumbs for nested routes (/products/category/item)
- Handle routes with breadcrumb data
- Handle routes without breadcrumb data
- Generate default labels from URL segments
- Mark last breadcrumb as non-clickable

#### 1.3-UNIT-013: Route guards block unauthorized access (P0)

**Test Case**: AuthGuard authorization logic
**Justification**: Security-critical - must prevent unauthorized access
**Mock Requirements**: AuthService, Router

**Test Scenarios**:
- Allow access for authenticated users
- Block access for unauthenticated users
- Redirect to login for protected routes
- Handle authentication state changes
- Validate role-based access (if applicable)

#### 1.3-UNIT-016: ThemeService toggles themes (P0)

**Test Case**: Theme switching functionality
**Justification**: Core service functionality with complex state management
**Mock Requirements**: localStorage, window.matchMedia

**Test Scenarios**:
- Toggle between light and dark themes
- Handle auto theme mode with system preference
- Persist theme selection to localStorage
- Apply theme classes to document body
- Handle localStorage unavailability gracefully

### Integration Test Details

#### 1.3-INT-001: Header integrates with AuthService (P0)

**Test Case**: Header component authentication integration
**Justification**: Critical user authentication display
**Test Environment**: TestBed with mocked AuthService

**Test Scenarios**:
- Display user menu for authenticated users
- Hide user menu for unauthenticated users
- Update display when authentication state changes
- Handle logout functionality correctly

#### 1.3-INT-003: Breadcrumbs update on route changes (P0)

**Test Case**: Breadcrumb service router integration
**Justification**: Core navigation functionality
**Test Environment**: TestBed with RouterTestingModule

**Test Scenarios**:
- Breadcrumbs update on NavigationEnd events
- Breadcrumbs rebuild for different route structures
- Handle route data correctly for breadcrumb labels
- Subscribe/unsubscribe patterns work correctly

#### 1.3-INT-005: Lazy loading modules load correctly (P0)

**Test Case**: Route lazy loading functionality
**Justification**: Core routing architecture
**Test Environment**: E2E or integration with real routing

**Test Scenarios**:
- Products module loads on /products route
- Cart module loads on /cart route
- Orders module loads on /orders route
- Admin module loads on /admin route
- Route chunks are split correctly

### E2E Test Details

#### 1.3-E2E-003: User navigates through protected routes (P0)

**Test Case**: Complete authentication and navigation journey
**Justification**: Revenue-critical user flow validation
**Test Environment**: Full application with test authentication

**Test Scenarios**:
- Unauthenticated user redirected to login
- User can login and access protected routes
- Protected routes display correctly for authenticated users
- Logout redirects appropriately
- Route guards work across different protected sections

**Performance Risks**:
- 1.3-INT-005: Lazy loading effectiveness

**User Experience Risks**:
- 1.3-E2E-001, 1.3-E2E-002: Navigation usability

## Test Environment Requirements

### Unit Tests
- **Framework**: Jest with Angular Testing Library
- **Mocks**: AuthService, Router, localStorage, window.matchMedia
- **Execution**: Isolated component testing

### Integration Tests
- **Framework**: Angular TestBed
- **Dependencies**: RouterTestingModule, HttpClientTestingModule
- **Environment**: In-memory routing and services

### E2E Tests
- **Framework**: Cypress or Playwright
- **Environment**: Full application with test data
- **Browser**: Chrome headless + manual cross-browser validation

## Recommended Execution Order

### Phase 1: Critical Path Validation (P0)
1. Run all P0 unit tests first (fast feedback on core logic)
2. Execute P0 integration tests (routing and service integration)
3. Run P0 E2E test (authentication flow validation)

### Phase 2: Core Functionality (P1)
1. P1 unit tests (component rendering and behavior)
2. P1 integration tests (responsive behavior, complex interactions)
3. P1 E2E tests (main navigation journeys)

### Phase 3: Polish and Edge Cases (P2+)
1. P2 unit tests (secondary features)
2. P3 tests if time permits

## Test Maintenance Considerations

**Stability Factors**:
- Unit tests most stable (isolated logic)
- Integration tests moderately stable (component contracts)
- E2E tests least stable (full UI interactions)

**Update Triggers**:
- Route structure changes → Update integration tests
- Authentication flow changes → Update P0 tests
- UI component changes → Update unit tests
- New navigation features → Add appropriate test level

## Quality Gates

**Minimum Required Coverage**:
- All P0 tests must pass before deployment
- P1 tests should pass (can deploy with known issues if documented)
- P2+ tests nice to have

**Performance Thresholds**:
- Unit tests: <5 seconds total execution
- Integration tests: <30 seconds total execution
- E2E tests: <2 minutes per test
